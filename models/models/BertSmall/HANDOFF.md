# HANDOFF — BertSmall (`prajjwal1/bert-small`) ModelTest e2e workload

Model link: <https://huggingface.co/prajjwal1/bert-small>
(`library: transformers`, F32 `pytorch_model.bin` 116,270,890 B, `vocab.txt`; commit
`0ec5f86f27c1a77d704439db5e01c307ea11b9d4` — reported by the HF Hub API and confirmed by the
local checkpoint load, see **Artifacts**). Config (read from the cached `config.json`, which is
the checkpoint's own file): hidden size 512, 4 hidden layers, 8 attention heads, intermediate
size 2048, `hidden_act: "gelu"` (the erf-exact form of `BertIntermediate`), vocab 30522, max
positions 512. License: MIT.

Stage: `workload` (initial model adaptation). chip: `pebble` — **intended future bind target,
NOT yet bound** (this stage adds no chip layout; the e2e `models/archs/buckyball/pebble/BertSmall/`
layout, the bbdev `MODEL_LAYOUT` entry and the parent `build.py::_MODELS` entry do not exist —
see **Known Limitation** #2).

Precedents followed: upstream `models/Bert/` (the family precedent — MNLI Bert importer /
`bert-main.cpp` driver / CMake shape) and the Bert-family MLM form of the BertTiny/BertMini
workloads (fixed-sentence masked-LM full-output contract, importer/checker/driver/HANDOFF
shape; in-tree copies were removed from the fork on 2026-09-06 — only read-only quarantine
copies exist for form reference). Everything below was executed on this checkout; every claim
cites a command output or a file path.

The `@forward` signature `bertsmall-main.cpp` is written against — read from the emitted
`output/forward.mlir`, not assumed:

```mlir
func.func @forward(%arg0: memref<28795194xf32>, %arg1: memref<512xi64>,
                   %arg2: memref<1x11xi64>, %arg3: memref<1x11xi64>, %arg4: memref<1x11xi64>)
  -> memref<1x11x30522xf32>
```

BERT takes a **`token_type_ids`** runtime input (`%arg3`, between `input_ids` and
`attention_mask`, matching `Bert/bert-main.cpp`'s call order). The traced graph lifts the
checkpoint's trainable tensors; the tied MLM decoder (`cls.predictions.decoder.weight` IS
`bert.embeddings.word_embeddings.weight`) is lifted once, so `arg0.data` holds exactly the
28,795,194 trainable float32 elements reported by the importer's bit-exact read-back.

## Canonical Reference

Produced with the **official implementation** (upstream `transformers 5.5.4`,
`torch 2.12.0`, CPU), never with a hand-written reimplementation, and never reduced to an argmax:

```
python3 pytorch-bertsmall-mlm.py --write-reference
-> wrote .../reference/bertsmall_mlm_logits_f32.bin (1342968 bytes, sha256 477af53e306c17a9...)
-> wrote .../reference/reference_manifest.json
-> reference logits shape=(1, 11, 30522) cpu_inference=0.081s
```

* Fixed input (from `reference_manifest.json`): `"The quick brown fox jumps over the lazy dog"`
  → `input_ids = [101, 1996, 4248, 2829, 4419, 14523, 2058, 1996, 13971, 3899, 102]`,
  `token_type_ids = [0] * 11`, `attention_mask = [1] * 11`. The sentence contains no
  `[MASK]`/`[SEP]` substring so upstream WordPiece and buddy's C++ `tokenizeBert` agree, and it
  is exactly SEQ_LEN = 11 tokens once `[CLS]`/`[SEP]` are added.
* Canonical tensor: `bertsmall_mlm_logits_f32.bin`, shape `[1, 11, 30522]`, float32,
  `sha256 477af53e306c17a97ddc0a1842687dc675e5caf94a29ade96f8b492088851ee0`.
* **Discrete expectation** (the driver's fail-hard contract, `kExpectedArgmaxIds` in
  `bertsmall-main.cpp`): the per-position argmax token ids of the canonical tensor are
  `[4419, 1996, 4248, 2829, 4419, 14523, 2058, 1996, 13971, 3899, 3899]` — positions 1–9
  re-predict the sentence words (`the quick brown fox jumps over the lazy dog`), and the
  `[CLS]`/`[SEP]` positions land on `fox`/`dog` (manifest `top_k_per_position[].top[0].token_id`).
* **Reproducibility:** a second run into a different directory
  (`--reference-dir .dsh/bs-ref2`) produced byte-identical output —
  `cmp reference/bertsmall_mlm_logits_f32.bin .dsh/bs-ref2/bertsmall_mlm_logits_f32.bin`
  → `REF-REPRO: byte-identical`.
* **Agreed tolerance:** `np.allclose(atol=1e-3, rtol=1e-3)` on the *complete* logits tensor
  (335,742 elements), plus exact `argmax` and exact top-5 token-id agreement, plus
  `relative_l2_error` reported for transparency — the same bar the Bert-family MLM precedents
  use, covering the float32 summation-order gap between upstream aten kernels and the
  TOSA/LLVM codegen path (measured `max_abs_diff` 4.2e-5, see **Local Run**; the lone
  `max_rel_diff` outlier is discussed in **Known Limitation** #5).

## Local Run

**Device: host CPU** (x86-64). `torch.cuda.is_available()` → `False` on this host; the official
single forward is **0.081 s** (second run 0.023 s) and the full TOSA→LLVM jit inference of the
imported graph is **9.94 s**, at (not above) the 10 s threshold in the playbook.

Environment (nix develop of the buckyball repo; `result/bin/python3` = Python 3.14.6 with
`torch 2.12.0`, `transformers 5.5.4`, `huggingface_hub 1.16.0`):

```bash
cd /home/ROXY/code/bb_work/buckyball
export BB=$PWD RISCV=$BB/result
export BUDDY_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/build
export LLVM_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/llvm/build
export PYTHONPATH="$LLVM_MLIR_BUILD_DIR/tools/mlir/python_packages/mlir_core:$BUDDY_MLIR_BUILD_DIR/python_packages"
export HF_HUB_OFFLINE=1   # checkpoint seeded in the default hub cache (~/.cache/huggingface/hub)

cd bb-tests/workloads/src/ModelTest/e2e/models/models/BertSmall
# 1) canonical reference (official implementation)
python3 pytorch-bertsmall-mlm.py --write-reference
# 2) local run: AOT import + execute the imported graph on the host CPU
python3 import-bertsmall.py --output-dir output --jit-check \
        --dump-candidate output/jit_logits_f32.bin
# 3) independent re-check of the dumped output through the workload's own checker
python3 pytorch-bertsmall-mlm.py --check output/jit_logits_f32.bin
```

The **local carrier chosen for this stage is the importer's own host execution path** (step 2,
an `--jit-check`-style host run of the imported graph) plus the offline checker (step 3). This
carrier is a **team-side addition, not a general upstream form** (upstream's chip-agnostic
host form is the `.rax` + `buddy-cli` runner-plugin packaging, which BertSmall does not carry);
the `.rax` form was not chosen because it requires a runner plugin/manifest this model lacks.

Step 2 is the model-side run: it imports the model exactly as `CMakeLists.txt` does and then
executes **that same imported graph** on the host CPU through the buddy frontend's own
TOSA → LLVM pipeline and MLIR `ExecutionEngine` (`dynamo_run()`), i.e. a different numerical
path from the aten kernels that produced the reference. No `buddy-opt`, no `buddy-translate`,
no `buddy-llc`, no chip/core target is involved. Verbatim output (checkpoint-load noise trimmed):

## Build Binding

Configure and build were run through CMake/Ninja directly (the `bbdev workload --build` path
needs the chip layout that this stage deliberately does not add — see **Known Limitation** #2).
The upstream `e2e/models/lib/CMakeLists.txt` gate requires per-chip compiler targets
(`ModelTestCRunnerUtils requires Chip.pb compiler targets`), so a chip-less configure needs the
same shim bbdev injects: `BUCKYBALL_TARGETS` plus an ISA dir generated from the chip.pb
(`pb_to_target_registry.py --isa-dir`, the pebble chip.pb already installed under
`examples/chips/pebble/configs/generated/chip.pb`).

```bash
cd /home/ROXY/code/bb_work/buckyball
export BB=$PWD RISCV=$BB/result
export BUDDY_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/build
export LLVM_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/llvm/build
export PYTHONPATH="$LLVM_MLIR_BUILD_DIR/tools/mlir/python_packages/mlir_core:$BUDDY_MLIR_BUILD_DIR/python_packages"
export HF_HUB_OFFLINE=1
python3 compiler/scripts/pb_to_target_registry.py --repo $PWD \
  --chip-pb examples/chips/pebble/configs/generated/chip.pb \
  --isa-dir .dsh/bertsmall-isa --print-targets   # prints: pebble

cmake -S bb-tests/workloads/src/ModelTest/e2e/models -B .dsh/build-bertsmall -G Ninja \
      -DMODEL=bertsmall -DWORKLOAD_LIB_DIR=$BB/bb-tests/workloads/lib \
      -DPython3_EXECUTABLE=$BB/result/bin/python3 \
      -DBUCKYBALL_TARGETS=pebble -DBUCKYBALL_ISA_DIR=$BB/.dsh/bertsmall-isa
# -- Enabled model: bertsmall
# -- Configuring done (2.8s) / -- Generating done (0.0s)

rm -rf bb-tests/workloads/src/ModelTest/e2e/models/models/BertSmall/output
cmake --build .dsh/build-bertsmall --target bertsmall-model-build   # BUILD wall ≈ 30 s
ninja     -C .dsh/build-bertsmall     bertsmall-model-build         # "ninja: no work to do." (idempotent)
```

The build run prints the importer's own report (`arg0.data: 28795194 float32 (115180776 bytes)
bit-exact`, `arg1.data: 512 int64 (4096 bytes) bit-exact`) and produces the four files listed
in **Artifacts**, after `rm -rf .../BertSmall/output` — so the CMake target, not a manual run,
generated them.

## Known Limitation

1. **`bertsmall-main.cpp` is not compiled or run in this stage.** Linking it needs the chip-bound
   `buddy-opt`/`buddy-translate`/`buddy-llc` pipeline, explicitly out of scope here. It is checked
   two ways instead: its `extern "C"` declaration and sizes match the `@forward` signature read
   from the emitted `output/forward.mlir` (`memref<28795194xf32>`, `1x11x30522xf32` out), and
   `g++ -fsyntax-only -Wall` passes against the buddy headers (see **Build Binding**).
2. **BertSmall has no pebble-bind assets yet — it is NOT bound.** By design this stage adds no
   `archs/buckyball/pebble/BertSmall/` layout, no bbdev `MODEL_LAYOUT` entry and no parent
   `bb-tests/workloads/scripts/build.py::_MODELS` entry, so `workload --build '--chip pebble'`
   (the expected CI test of this round) cannot select this model yet — `chips_for_model()`
   returns an empty set for `bertsmall`. The chip-bind round (later stage, chip-lead territory)
   owns that work; `chip: pebble` in this round's checklist is an intention, not a binding.
3. **C++ tokenizer parity is asserted, not executed.** `Text::tokenizeBert` agrees with upstream
   WordPiece for the chosen sentence only because it contains no special-token substrings; that
   claim cannot be verified until the driver is linked (limitation #1).
4. **Parameter packing follows the Bert-family convention, enforced fail-hard**:
   `check_param_layout()` in the importer rejects any lifted tensor but the last that is not
   float32, or a non-int64 trailing buffer, and the bit-exact read-back re-verifies the blobs.
   Verified for this checkpoint: 28,795,194 float32 elements + 512 int64 (the
   `bert.embeddings.position_ids` buffer). A future checkpoint with several int64 buffers would
   need the importer changed — loudly.
5. **`max_rel_diff` is 1.68 while `mean_abs_diff` is 7.3e-6.** The relative figure comes from a
   few logits whose reference value sits near zero, where float32 reassociation dominates; this
   is why the agreed metric is `np.allclose(atol=1e-3, rtol=1e-3)` on the whole tensor plus
   relative-L2 (1.9e-6) plus exact argmax/top-5 token-id agreement, rather than a pure relative
   bound.
6. **Host-CPU jit inference is at the playbook threshold.** The single ExecutionEngine forward of
   the imported graph measured 9.94 s (28.5 s one-off jit compile, 115.2 MB parameters) — just
   below the 10 s per-inference CPU/GPU rule, on an otherwise loaded machine. The official
   aten forward is ~0.03–0.08 s. A busier host may tip the jit inference over 10 s; GPU was not
   needed for the measurements recorded here.
7. **The checkpoint carries weights the MLM graph does not use** (`bert.pooler.*`,
   `cls.seq_relationship.*`, and an old persistent `bert.embeddings.position_ids` copy);
   transformers reports them as UNEXPECTED at load ("can be ignored", per its own note) and they
   are not among the lifted graph tensors.
8. **A 1.34 MB binary reference file is committed.** It is the full canonical logits tensor, which
   the "compare the complete output, not just an argmax" rule calls for; it is regenerable and
   pinned by the sha256 in `reference/reference_manifest.json`.
9. **Hub cache environment.** `huggingface.co` direct fetches were slow/stalled on this host; the
   `pytorch_model.bin` blob was completed through the `hf-mirror.com` redirect chain and verified
   against the LFS oid (`sha256` = blob name `3452e711…`, size 116,270,890 B) before use. One
   earlier resume attempt through the mirror produced non-verifying bytes and was discarded; the
   committed numbers above come only from the sha-verified blob. The default hub cache
   (`~/.cache/huggingface/hub`) holds the three files of commit `0ec5f86f…`.
10. **`__pycache__/` and `output/`** are produced by running the scripts; both are ignored
   (`models/models/.gitignore`, this directory's `.gitignore`).
