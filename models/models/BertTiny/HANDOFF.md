# HANDOFF — BertTiny (`prajjwal1/bert-tiny`) ModelTest e2e workload

Model link: <https://huggingface.co/prajjwal1/bert-tiny>
(`library: transformers`, F32 `pytorch_model.bin` 17,756,393 B, `vocab.txt`; commit
`6f75de8b60a9f8a2fdf7b69cbd86d9e64bcb3837` — reported by the HF Hub API and confirmed by the
local checkpoint load, see **Artifacts**). Config: 2 hidden layers, hidden size 128, 2 heads,
intermediate 512, `hidden_act: "gelu"` (the erf-exact form of `BertIntermediates`), vocab 30522.

Stage: `workload` (initial model adaptation). chip: `toy` — **intended future bind target, NOT
yet bound** (this stage adds no chip layout; see **Known Limitation** #2).

Precedents followed: `models/DistilBert/` (MLM full-output contract, importer/checker/HANDOFF
shape) and `models/Bert/` (`token_type_ids` runtime input and driver argument order).
Everything below was executed on this checkout; every claim cites a command output or a file path.

## Artifacts

Directory: `bb-tests/workloads/src/ModelTest/e2e/models/models/BertTiny/`

| File | Role |
| --- | --- |
| `import-berttiny.py` | buddy frontend AOT importer. Traces `BertForMaskedLM.from_pretrained("prajjwal1/bert-tiny")` with `DynamoCompiler(primary_registry=tosa.ops_registry, aot_autograd_decomposition=inductor_decomp)`, fuses with `simply_fuse`, writes `forward.mlir`, `subgraph0.mlir`, `arg0.data`, `arg1.data`, asserts the packing rule fail-hard (`check_param_layout`: every param but the last float32, the last int64) and requires a bit-exact read-back. Optional `--jit-check` executes the imported graph on the host CPU (see **Local Run**). |
| `pytorch-berttiny-mlm.py` | Canonical-reference producer and the workload's full-output checker. Owns the fixed case (`SENTENCE`, `SEQ_LEN = 11`), `VOCAB_SIZE = 30522` and the agreed tolerance (`atol = rtol = 1e-3`). |
| `berttiny-main.cpp` | Model-side C++ driver: loads `arg0.data` / `arg1.data`, tokenizes the fixed sentence with `Text<long long, 2>::tokenizeBert(vocab.txt, 11)`, builds all-zero `token_type_ids` and all-one `attention_mask`, calls `_mlir_ciface_forward`, dumps the complete logits to `berttiny_logits_f32.bin` and prints per-position top-5. |
| `CMakeLists.txt` | `berttiny-model-build` custom target that runs the importer. Model side only: no arch, core-count, quant or trace binding. |
| `vocab.txt` | WordPiece vocabulary from the checkpoint, 30522 lines; byte-identical to `models/Bert/vocab.txt` and `models/DistilBert/vocab.txt` (all md5 `64800d5d8528ce344256daf115d4965e`; the hub cache blob name `fb140275c155a9c7…` is shared with distilbert's vocab). |
| `.gitignore` | Ignores the generated blobs when the importer is run with `--output-dir .`; `reference/` stays committed on purpose. |
| `reference/berttiny_mlm_logits_f32.bin` | Canonical full masked-LM logits, raw little-endian float32, C order, 1,342,968 bytes. |
| `reference/reference_manifest.json` | Input ids, shape, dtype, device, sha256, tolerance, per-position top-5. |
| `output/` | Generated by the importer; not tracked (`output/` and `__pycache__/` are ignored by `models/models/.gitignore`). |

Generated artifact sizes (`ls -la .../BertTiny/output`, from the build in **Build Binding**):

```
-rw-r--r-- 1 ROXY ROXY 17666792 arg0.data      # 4,416,698 float32 = the model's trainable-parameter count
-rw-r--r-- 1 ROXY ROXY     4096 arg1.data      # 512 int64 (bert.embeddings.position_ids buffer)
-rw-r--r-- 1 ROXY ROXY    20346 forward.mlir   # 115 lines
-rw-r--r-- 1 ROXY ROXY    53054 subgraph0.mlir # 565 lines
```

The `@forward` signature `berttiny-main.cpp` is written against — read from the emitted
`output/forward.mlir`, not assumed:

```mlir
func.func @forward(%arg0: memref<4416698xf32>, %arg1: memref<512xi64>,
                   %arg2: memref<1x11xi64>, %arg3: memref<1x11xi64>, %arg4: memref<1x11xi64>)
  -> memref<1x11x30522xf32>
```

BERT takes a **`token_type_ids`** runtime input (`%arg3`, between `input_ids` and
`attention_mask`, matching `Bert/bert-main.cpp`'s call order), one more than
`DistilBert/distilbert-main.cpp` carries. The traced graph lifts 43 parameters
(42 float32 + the trailing int64 `position_ids` buffer); the tied MLM decoder
(`cls.predictions.decoder.weight` IS `bert.embeddings.word_embeddings.weight`) is
lifted once, so `arg0.data` holds exactly the 4,416,698 trainable float32 elements
reported by `sum(p.numel() for p in model.parameters())`.

## Canonical Reference

Produced with the **official implementation** (upstream `transformers 5.5.4`,
`torch 2.12.0`, CPU), never with a hand-written reimplementation, and never reduced to an argmax:

```
python3 pytorch-berttiny-mlm.py --write-reference
-> wrote .../reference/berttiny_mlm_logits_f32.bin (1342968 bytes, sha256 3e615479bafa5edb...)
-> reference logits shape=(1, 11, 30522) cpu_inference=0.025s
```

* Fixed input (from `reference_manifest.json`): `"The quick brown fox jumps over the lazy dog"`
  → `input_ids = [101, 1996, 4248, 2829, 4419, 14523, 2058, 1996, 13971, 3899, 102]`,
  `token_type_ids = [0] * 11`, `attention_mask = [1] * 11`. Same sentence and ids as the
  DistilBert precedent (shared 30522-word vocab); the sentence contains no
  `[MASK]`/`[SEP]` substring so upstream WordPiece and buddy's C++ `tokenizeBert` agree.
* Canonical tensor: `berttiny_mlm_logits_f32.bin`, shape `[1, 11, 30522]`, float32,
  `sha256 3e615479bafa5edb1aa5ee155b80f5535c768d404e7cf65d1ed3a2aff866f543`.
* **Reproducibility:** a second run into a different directory
  (`--reference-dir .dsh/bt-ref2`) produced byte-identical output —
  `cmp reference/berttiny_mlm_logits_f32.bin .dsh/bt-ref2/berttiny_mlm_logits_f32.bin`
  → `REF-REPRO: byte-identical`.
* **Agreed tolerance:** `np.allclose(atol=1e-3, rtol=1e-3)` on the *complete* logits tensor
  (335,742 elements), plus exact `argmax` and exact top-5 token-id agreement, plus
  `relative_l2_error` reported for transparency — the same bar the DistilBert precedent uses,
  covering the float32 summation-order gap between upstream aten kernels and the TOSA/LLVM
  codegen path (measured `max_abs_diff` is 3.1e-5, see **Local Run**).

## Local Run

**Device: host CPU** (x86-64). `torch.cuda.is_available()` → `False` on this host, and CPU is
comfortably sufficient: the official single forward is **0.025 s** and even the full TOSA→LLVM
jit inference is **3.54 s**, both far below the 10 s threshold in the playbook.

Environment (nix env of the buckyball repo; `result/bin/python3` = Python 3.14.6 with
`torch 2.12.0`, `transformers 5.5.4`, `huggingface_hub 1.16.0`):

```bash
cd /home/ROXY/code/bb_work/buckyball
export BB=$PWD RISCV=$BB/result
export BUDDY_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/build
export LLVM_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/llvm/build
export PYTHONPATH="$LLVM_MLIR_BUILD_DIR/tools/mlir/python_packages/mlir_core:$BUDDY_MLIR_BUILD_DIR/python_packages"
export HF_HOME=$BB/.dsh/hf-cache HF_HUB_OFFLINE=1   # checkpoint staged there, see Known Limitation #6

cd bb-tests/workloads/src/ModelTest/e2e/models/models/BertTiny
# 1) canonical reference (official implementation)
python3 pytorch-berttiny-mlm.py --write-reference
# 2) local run: AOT import + execute the imported graph on the host CPU
python3 import-berttiny.py --output-dir output --jit-check \
        --dump-candidate output/jit_logits_f32.bin
# 3) independent re-check of the dumped output through the workload's own checker
python3 pytorch-berttiny-mlm.py --check output/jit_logits_f32.bin
```

executes **that same imported graph** on the host CPU through the buddy frontend's own
TOSA → LLVM pipeline and MLIR `ExecutionEngine` (`dynamo_run()`), i.e. a different numerical
path from the aten kernels that produced the reference. No `buddy-opt`, no `buddy-translate`,
no `buddy-llc`, no chip/core target is involved. Verbatim output (checkpoint-load noise trimmed):

needs the chip layout that this stage deliberately does not add — see **Known Limitation** #2).
`-DWORKLOAD_LIB_DIR` must be passed explicitly (established by the DistilBert precedent: with
the checked-in default the configure fails for every model, this one included).

```bash

      -DPython3_EXECUTABLE=$BB/result/bin/python3
```

## Known Limitation

1. **`berttiny-main.cpp` is not compiled or run in this stage.** Linking it needs the chip-bound
   `buddy-opt`/`buddy-translate`/`buddy-llc` pipeline, explicitly out of scope here. It is checked
   two ways instead: its `extern "C"` declaration matches the `@forward` signature read from the
   emitted `output/forward.mlir`, and `g++ -fsyntax-only -Wall` passes against the buddy headers
   (see **Build Binding**).
2. **`workload --build --chip toy` cannot select this model yet.** By design this stage adds no
   `archs/buckyball/toy/BertTiny/` layout and no bbdev `MODEL_LAYOUT` / `build.py::_MODELS`
   entry, so `chips_for_model()` returns an empty set and the step would abort with
   `unsupported_chip_model`. The chip-bind round (later stage, chip-lead territory) owns that
   work; until then `toy` in the checklist is an intention, not a binding.
3. **C++ tokenizer parity is asserted, not executed.** `Text::tokenizeBert` agrees with upstream
   WordPiece for the chosen sentence only because it contains no special-token substrings; that
   claim cannot be verified until the driver is linked (limitation #1).
4. **Parameter packing follows the Bert/DistilBert convention, now enforced fail-hard**:
   `check_param_layout()` in the importer rejects any lifted tensor but the last that is not
   float32, or a non-int64 trailing buffer, and the bit-exact read-back re-verifies the blobs.
   Verified for this checkpoint: 43 params, 4,416,698 float32 elements + 512 int64 (the
   `bert.embeddings.position_ids` buffer). A future checkpoint with several int64 buffers would
   need the importer changed — loudly.
5. **`max_rel_diff` is 0.144 while `mean_abs_diff` is 3.74e-6.** The relative figure comes from a
   few logits whose reference value sits near zero, where float32 reassociation dominates; this
   is why the agreed metric is `np.allclose(atol=1e-3, rtol=1e-3)` on the whole tensor plus
   relative-L2 (6.74e-7) plus exact top-5 id agreement, rather than a pure relative bound.
6. **Environment notes (not workload defects).** `huggingface.co` is not directly reachable and
   `hf-mirror.com` answers the hub client's per-file `HEAD` with a 308 that `huggingface_hub
   1.16` does not follow, so `snapshot_download` aborts with `LocalEntryNotFoundError`. The
   checkpoint was therefore seeded into `HF_HOME=$BB/.dsh/hf-cache` by redirect-following GETs
   through the mirror (scratch script `.dsh/seed-berttiny-cache.py`, git-ignored), with each
   fetched file verified against the sha the tree API declares. Reviewers need the same
   `prajjwal1/bert-tiny` files (config.json, vocab.txt, pytorch_model.bin; commit
   `6f75de8b60a9f8a2fdf7b69cbd86d9e64bcb3837`) in their `HF_HOME`, and every run here used
   `HF_HUB_OFFLINE=1`.
7. **The checkpoint carries weights the MLM graph does not use** (`bert.pooler.*`,
   `cls.seq_relationship.*`, and an old persistent `bert.embeddings.position_ids` copy);
   transformers reports them as UNEXPECTED at load ("can be ignored", per its own note) and they
   are not among the 43 lifted graph parameters.
8. **A 1.34 MB binary reference file is committed.** It is the full canonical logits tensor, which
   the "compare the complete output, not just an argmax" rule calls for; it is regenerable and
   pinned by the sha256 in `reference/reference_manifest.json`.
9. **`__pycache__/` and `output/`** are produced by running the scripts; both are ignored
   (`models/models/.gitignore`, this directory's `.gitignore`).
