# HANDOFF — BertMedium (`prajjwal1/bert-medium`) ModelTest e2e workload

Model link: <https://huggingface.co/prajjwal1/bert-medium>
(`library: transformers`, F32 `pytorch_model.bin` 166,734,612 B, `vocab.txt`; commit
`ce27ec2944bd32b66ed837edb9c77eb7301b8ecc` — reported by the HF Hub API and confirmed by the
local checkpoint load, see **Artifacts**). Config (read from the cached `config.json`, which is
the checkpoint's own file): hidden size 512, **8 hidden layers**, 8 attention heads,
intermediate size 2048, `hidden_act: "gelu"` (the erf-exact form of `BertIntermediate`), vocab
30522, max positions 512. License: MIT. Architecturally identical to `prajjwal1/bert-small`
except the encoder layer count (4 → 8).

Stage: `workload` (initial model adaptation). chip: `pebble` — **intended future bind target,
NOT yet bound** (this stage adds no chip layout; the e2e
`models/archs/buckyball/pebble/BertMedium/` layout, the bbdev `MODEL_LAYOUT` entry and the
parent `bb-tests/workloads/scripts/build.py::_MODELS` entry do not exist — see **Known
Limitation** #1).

Precedents followed: upstream `models/Bert/` (the family precedent) and the in-repo
`models/BertSmall/` realization (commit `77ae43b`, the closest same-family MLM workload).
Everything below was executed on this checkout; every claim cites a command output or a file
path.

Directory: `bb-tests/workloads/src/ModelTest/e2e/models/models/BertMedium/`

Checkpoint facts verified on this machine (reads of the seeded hub cache at
`~/.cache/huggingface/hub`, commit `ce27ec2944bd32b66ed837edb9c77eb7301b8ecc`): the model
file is 166,734,612 B and its sha256 equals the LFS oid
`916bbdfc8e404b2a2322a42efeea2375945c70d97c576f6bb0be8b3590816b5c` (the blob name in the
cache). `BertForMaskedLM` reports the same UNEXPECTED keys as bert-small at load
(`cls.seq_relationship.*`, `bert.pooler.*`, an old persistent
`bert.embeddings.position_ids`) — transformers says they can be ignored; they are not lifted
into the traced graph. Parameter count read from the loaded checkpoint
(`sum(p.numel() for p in model.parameters())`): **41,404,730 float32** + the 512-int64
`position_ids` buffer (a buffer, not a parameter — printed separately).

Generated artifact sizes (`ls -la .../BertMedium/output`, from the build in **Build Binding**):

```
-rw-r--r-- 1 ROXY ROXY 165618920 arg0.data      # 41,404,730 float32 = the model's trainable-parameter count
-rw-r--r-- 1 ROXY ROXY      4096 arg1.data      # 512 int64 (bert.embeddings.position_ids buffer)
-rw-r--r-- 1 ROXY ROXY     64838 forward.mlir   # 343 lines
-rw-r--r-- 1 ROXY ROXY    170083 subgraph0.mlir # 1,737 lines
```

The `@forward` signature `bertmedium-main.cpp` is written against — read from the emitted
`output/forward.mlir`, not assumed:

```mlir
func.func @forward(%arg0: memref<41404730xf32>, %arg1: memref<512xi64>,
                   %arg2: memref<1x11xi64>, %arg3: memref<1x11xi64>, %arg4: memref<1x11xi64>)
  -> memref<1x11x30522xf32>
```

BERT takes a **`token_type_ids`** runtime input (`%arg3`, between `input_ids` and
`attention_mask`, matching `Bert/bert-main.cpp`'s call order). The traced graph lifts the
checkpoint's trainable tensors; the tied MLM decoder (`cls.predictions.decoder.weight` IS
`bert.embeddings.word_embeddings.weight`) is lifted once, so `arg0.data` holds exactly the
41,404,730 trainable float32 elements reported by the importer's bit-exact read-back.

## Canonical Reference

Produced with the **official implementation** (upstream `transformers 5.5.4`,
`torch 2.12.0`, CPU), never with a hand-written reimplementation, and never reduced to an argmax:

```
python3 pytorch-bertmedium-mlm.py --write-reference
-> wrote .../reference/bertmedium_mlm_logits_f32.bin (1342968 bytes, sha256 9237012649fbe970...)
-> wrote .../reference/reference_manifest.json
-> reference logits shape=(1, 11, 30522) cpu_inference=0.158s
```

* Fixed input (from `reference_manifest.json`): `"The quick brown fox jumps over the lazy dog"`
  → `input_ids = [101, 1996, 4248, 2829, 4419, 14523, 2058, 1996, 13971, 3899, 102]`,
  `token_type_ids = [0] * 11`, `attention_mask = [1] * 11` — the same fixed case as the
  BertSmall workload (the sentence contains no `[MASK]`/`[SEP]` substring so upstream
  WordPiece and buddy's C++ `tokenizeBert` agree, and it is exactly SEQ_LEN = 11 tokens once
  `[CLS]`/`[SEP]` are added).
* Canonical tensor: `bertmedium_mlm_logits_f32.bin`, shape `[1, 11, 30522]`, float32,
  `sha256 9237012649fbe970f9499325042a8a15aa95a11a9893e581e0c39565a7978baf`.
* **Discrete expectation** (the driver's fail-hard contract, `kExpectedArgmaxIds` in
  `bertmedium-main.cpp`): the per-position argmax token ids of the canonical tensor are
  `[3899, 1996, 4248, 2829, 4419, 14523, 2058, 1996, 13971, 3899, 1010]` — positions 1–9
  re-predict the sentence words (`the quick brown fox jumps over the lazy dog`), while the
  `[CLS]` position lands on `dog` and the `[SEP]` position on `,` (manifest
  `top_k_per_position[].top[0].token_id`). These landing points are *measured from the
  official implementation*; they differ from BertSmall's at positions 0 and 10 because of the
  4 extra encoder layers — no value was copied from any precedent.
* **Reproducibility:** a second run into a different directory
  (`--reference-dir .dsh/bertmedium/ref2`) produced byte-identical output —
  `cmp reference/bertmedium_mlm_logits_f32.bin .dsh/bertmedium/ref2/bertmedium_mlm_logits_f32.bin`
  → `REF-REPRO: byte-identical`.
* **Agreed tolerance:** `np.allclose(atol=1e-3, rtol=1e-3)` on the *complete* logits tensor
  (335,742 elements), plus exact `argmax` and exact top-5 token-id agreement, plus
  `relative_l2_error` reported for transparency — the same bar the Bert-family MLM precedents
  use, covering the float32 summation-order gap between upstream aten kernels and the
  TOSA/LLVM codegen path (measured `max_abs_diff` 3.4e-5, see **Local Run**; the lone
  `max_rel_diff` outlier is discussed in **Known Limitation** #7).

## Local Run

**Device: host CPU** (x86-64). The host has an NVIDIA A800, but no CUDA-enabled Python
toolchain exists in this environment (`torch.cuda.is_available()` → `False` in
`result/bin/python3`, and the buddy ExecutionEngine is a host-CPU LLVM JIT with no GPU codegen
path — see **Known Limitation** #6). The official single forward is **0.158 s** (second run
0.113 s); the full TOSA→LLVM jit inference of the imported graph is **22.43 s**.

Environment (nix develop of the buckyball repo; `result/bin/python3` = Python 3.14.6 with
`torch 2.12.0`, `transformers 5.5.4`, `huggingface_hub 1.16.0`):

```bash
cd /home/ROXY/code/bb_work/buckyball
export BB=$PWD RISCV=$BB/result
export BUDDY_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/build
export LLVM_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/llvm/build
export PYTHONPATH="$LLVM_MLIR_BUILD_DIR/tools/mlir/python_packages/mlir_core:$BUDDY_MLIR_BUILD_DIR/python_packages"
export HF_HUB_OFFLINE=1   # checkpoint seeded in the default hub cache (~/.cache/huggingface/hub)

cd bb-tests/workloads/src/ModelTest/e2e/models/models/BertMedium
# 1) canonical reference (official implementation)
python3 pytorch-bertmedium-mlm.py --write-reference
# 2) local run: AOT import + execute the imported graph on the host CPU
python3 import-bertmedium.py --output-dir output --jit-check \
        --dump-candidate output/jit_logits_f32.bin
# 3) independent re-check of the dumped output through the workload's own checker
python3 pytorch-bertmedium-mlm.py --check output/jit_logits_f32.bin
```

The **local carrier chosen for this stage is the importer's own host execution path** (step 2,
an `--jit-check`-style host run of the imported graph) plus the offline checker (step 3). This
carrier is a **team-side addition, not a general upstream form** (upstream's chip-agnostic
host form is the `.rax` + `buddy-cli` runner-plugin packaging, which BertMedium does not
carry); the `.rax` form was not chosen because it requires a runner plugin/manifest this model
lacks. Same carrier decision as the BertSmall round.

Step 2 is the model-side run: it imports the model exactly as `CMakeLists.txt` does and then
executes **that same imported graph** on the host CPU through the buddy frontend's own
TOSA → LLVM pipeline and MLIR `ExecutionEngine` (`dynamo_run()`), i.e. a different numerical
path from the aten kernels that produced the reference. No `buddy-opt`, no `buddy-translate`,
no `buddy-llc`, no chip/core target is involved. Verbatim output (checkpoint-load noise trimmed):

## Build Binding

Configure and build were run through CMake/Ninja directly (the `bbdev workload --build` path
needs the chip layout that this stage deliberately does not add — see **Known Limitation** #1).
The upstream `e2e/models/lib/CMakeLists.txt` gate requires per-chip compiler targets
(`ModelTestCRunnerUtils requires Chip.pb compiler targets`), so a chip-less configure needs the
same shim bbdev injects: `BUCKYBALL_TARGETS` plus an ISA dir generated from the chip.pb
(`pb_to_target_registry.py --isa-dir`, the pebble chip.pb already installed under
`examples/chips/pebble/configs/generated/chip.pb`).

```bash
cd /home/ROXY/code/bb_work/buckyball
export BB=$PWD RISCV=$BB/result
export BUDDY_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/build
export LLVM_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/llvm/build
export PYTHONPATH="$LLVM_MLIR_BUILD_DIR/tools/mlir/python_packages/mlir_core:$BUDDY_MLIR_BUILD_DIR/python_packages"
export HF_HUB_OFFLINE=1
python3 compiler/scripts/pb_to_target_registry.py --repo $PWD \
  --chip-pb examples/chips/pebble/configs/generated/chip.pb \
  --isa-dir .dsh/bertmedium-isa --print-targets   # prints: pebble

cmake -S bb-tests/workloads/src/ModelTest/e2e/models -B .dsh/build-bertmedium -G Ninja \
      -DMODEL=bertmedium -DWORKLOAD_LIB_DIR=$BB/bb-tests/workloads/lib \
      -DPython3_EXECUTABLE=$BB/result/bin/python3 \
      -DBUCKYBALL_TARGETS=pebble -DBUCKYBALL_ISA_DIR=$BB/.dsh/bertmedium-isa
# -- Enabled model: bertmedium
# -- Configuring done (2.1s) / -- Generating done (0.0s)

rm -rf bb-tests/workloads/src/ModelTest/e2e/models/models/BertMedium/output
cmake --build .dsh/build-bertmedium --target bertmedium-model-build   # BUILD wall ≈ 2-3 min
```

The build run prints the importer's own report (`arg0.data: 41404730 float32 (165618920
bytes) bit-exact`, `arg1.data: 512 int64 (4096 bytes) bit-exact`) and produces the four files
listed in **Artifacts**, after `rm -rf .../BertMedium/output` — so the CMake target, not a
manual run, generated them.

The driver was compile-checked against the real headers (it cannot be *linked* without a chip

## Known Limitation

1. **`bertmedium-main.cpp` is not compiled or run in this stage.** Linking it needs the
   chip-bound `buddy-opt`/`buddy-translate`/`buddy-llc` pipeline, explicitly out of scope here.
   It is checked two ways instead: its `extern "C"` declaration and sizes match the `@forward`
   signature read from the emitted `output/forward.mlir` (`memref<41404730xf32>`,
   `1x11x30522xf32` out), and `g++ -fsyntax-only -Wall` passes against the buddy headers (see
   **Build Binding**).
2. **BertMedium has no pebble-bind assets yet — it is NOT bound.** By design this stage adds no
   `archs/buckyball/pebble/BertMedium/` layout, no bbdev `MODEL_LAYOUT` entry and no parent
   `bb-tests/workloads/scripts/build.py::_MODELS` entry, so `workload --build '--chip pebble'`
   (the expected CI test of this round) cannot select this model yet — `chips_for_model()`
   returns an empty set for `bertmedium`. The chip-bind round (later stage, chip-lead territory)
   owns that work; `chip: pebble` in this round's checklist is an intention, not a binding.
3. **C++ tokenizer parity is asserted, not executed.** `Text::tokenizeBert` agrees with upstream
   WordPiece for the chosen sentence only because it contains no special-token substrings; that
   claim cannot be verified until the driver is linked (limitation #1).
4. **Parameter packing follows the Bert-family convention, enforced fail-hard**:
   `check_param_layout()` in the importer rejects any lifted tensor but the last that is not
   float32, or a non-int64 trailing buffer, and the bit-exact read-back re-verifies the blobs.
   Verified for this checkpoint: 41,404,730 float32 elements + 512 int64 (the
   `bert.embeddings.position_ids` buffer). A future checkpoint with several int64 buffers would
   need the importer changed — loudly.
5. **BertMedium is bert-small with 4 extra encoder layers; every committed number is this
   checkpoint's own measurement.** The canonical argmax landing points `[3899, 1996, ...,
   1010]` differ from BertSmall's at positions 0 (`dog` vs `fox`) and 10 (`,` vs `dog`), which
   is the expected effect of the deeper stack — verified by running the official implementation,
   never copied from a precedent.
6. **Host-CPU jit inference exceeds the 10 s per-inference rule; GPU is not available for this
   path.** The single ExecutionEngine forward measured 22.43 s (100.6 s one-off jit compile,
   165.6 MB parameters). The playbook says to switch to local GPU when a single forward exceeds
   10 s; this environment cannot: `torch.cuda.is_available()` is False in the only Python
   toolchain (a CPU-only nix torch), and the buddy ExecutionEngine lowers to host-CPU LLVM JIT
   with no GPU codegen path — CUDA cannot accelerate it even on the host's A800. The canonical
   reference producer (official aten forward) is 0.113–0.158 s on CPU, well under the rule. A
   busier host would only make the jit path slower; this is recorded here rather than silently
   switching carriers.
7. **`max_rel_diff` is 7.72 while `mean_abs_diff` is 5.5e-6.** The relative figure comes from a
   few logits whose reference value sits near zero, where float32 reassociation dominates; this
   is why the agreed metric is `np.allclose(atol=1e-3, rtol=1e-3)` on the whole tensor plus
   relative-L2 (1.3e-6) plus exact argmax/top-5 token-id agreement, rather than a pure relative
   bound.
8. **The checkpoint carries weights the MLM graph does not use** (`bert.pooler.*`,
   `cls.seq_relationship.*`, and an old persistent `bert.embeddings.position_ids` copy);
   transformers reports them as UNEXPECTED at load ("can be ignored", per its own note) and they
   are not among the lifted graph tensors.
9. **A 1.34 MB binary reference file is committed.** It is the full canonical logits tensor,
   which the "compare the complete output, not just an argmax" rule calls for; it is
   regenerable and pinned by the sha256 in `reference/reference_manifest.json`.
10. **Hub cache environment.** This host reaches HuggingFace only through the local HTTP proxy
    (127.0.0.1:17900). Two environment quirks had to be worked around when seeding the cache:
    (a) `HF_ENDPOINT=https://hf-mirror.com` makes huggingface_hub reject the mirror's 308
    redirect to huggingface.co ("Distant resource does not seem to be on huggingface.co"), so
    downloads ran with `HF_ENDPOINT` unset and the proxy's `http(s)_proxy` vars kept; (b) the
    harness's `no_proxy`/`ALL_PROXY`/`NODE_USE_ENV_PROXY` env vars break httpx URL parsing in
    this Python (urllib treats any `*_proxy` var as a proxy scheme) and were stripped for the
    download process. The LFS blob (166,734,612 B) was downloaded in two resume segments and
    verified against its LFS oid sha256 `916bbdfc8e...` before use; the default hub cache
    (`~/.cache/huggingface/hub`) holds the three files of commit `ce27ec2944bd...`. The CI lane
    consumes committed generated assets with `HF_HUB_OFFLINE=1` — it does not download.
11. **`__pycache__/` and `output/`** are produced by running the scripts; both are ignored
    (`models/models/.gitignore`, this directory's `.gitignore`).
