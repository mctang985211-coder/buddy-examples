# HANDOFF — Pythia (`EleutherAI/pythia-70m`) ModelTest e2e workload

Model link: <https://huggingface.co/EleutherAI/pythia-70m>
(`library: gpt-neox`, `model_type: gpt_neox`, single `model.safetensors`
166,029,852 B, fp16 in the checkpoint and loaded fp32 here; hub commit
`a39f36b100fe8a5377810d56c3f4789b9c53ac42` — reported by the HF Hub API via
`buckyball_model_info` and confirmed by the local cache snapshot directory).
Config (read from the checkpoint's own `config.json`): GPTNeoXForCausalLM,
hidden size 512, **6 hidden layers**, 8 attention heads, intermediate 2048,
`hidden_act: "gelu"`, rotary 25% / base 10000, `use_parallel_residual: true`,
`tie_word_embeddings: false`, vocab 50304, max positions 2048. License: Apache
2.0. Parameter count read from the loaded checkpoint: **70,426,624 float32**
trainable parameters; the traced graph lifts them plus the 8-float32 rotary
`inv_freq` buffer, for a 70,426,632-element arg0.data blob.

Stage: `workload` (initial model adaptation). chip: `pebble` — **intended future
bind target, NOT yet bound** (this stage adds no chip layout; the e2e
`models/archs/buckyball/pebble/Pythia/` layout, the bbdev `MODEL_LAYOUT` entry
and the parent `bb-tests/workloads/scripts/build.py::_MODELS` entry do not exist
— see **Known Limitation** #2).

Precedents followed: upstream `models/Qwen3/` for the import pathway
(AutoModelForCausalLM + DynamoCompiler frontend, which gpt_neox falls into
unchanged) and the in-repo `models/BertMedium/` realization for the workload
discipline (reference/ artifacts, fail-hard expectations, HANDOFF). Everything
below was executed on this checkout; every claim cites a command output or a
file path.

## Canonical Reference

Produced with the **official implementation** (upstream `transformers 5.5.4`,
`torch 2.12.0`, CPU), never with a hand-written reimplementation:

```
python3 pythia-ppl.py --write-reference
-> wrote .../reference/pythia_logits_f32.bin (3219456 bytes, sha256 727b05fbea26b22c...)
-> wrote .../reference/reference_manifest.json
-> reference logits shape=(1, 16, 50304) cpu_inference=0.012s causal_ppl=21.084626
```

* Fixed input (from `reference_manifest.json`): the sentence
  `"Once upon a time there was a little girl who lived in a small village."`
  tokenizes with the official GPT-NeoX tokenizer to exactly 16 ids (no padding;
  the script fails hard otherwise):
  `input_ids = [10758, 2220, 247, 673, 627, 369, 247, 1652, 3226, 665, 6940,
  275, 247, 1355, 7773, 15]` = `['Once', 'Ġupon', 'Ġa', 'Ġtime', 'Ġthere',
  'Ġwas', 'Ġa', 'Ġlittle', 'Ġgirl', 'Ġwho', 'Ġlived', 'Ġin', 'Ġa', 'Ġsmall',
  'Ġvillage', '.']`.
* Canonical tensor: `reference/pythia_logits_f32.bin`, shape `[1, 16, 50304]`,
  float32, sha256 `727b05fbea26b22c007415fba90c94d936cc70d00bcf90ba8684d4b41e88ad9e`.
* **Canonical ppl (causal-LM loss over the shifted ids)**: `causal_ppl =
  21.084626` (loss 3.048544, official `labels=` forward).
* **Discrete expectation** (the driver's fail-hard contract,
  `kExpectedArgmaxIds` in `buddy-pythia-main.cpp`): the per-position argmax
  token ids of the canonical tensor are
  `[368, 253, 673, 13, 369, 247, 673, 673, 665, 369, 275, 253, 2419, 2419,
  275, 187]` — the ids predicted after each prompt token (tokens `Ġyou`, `Ġthe`,
  `Ġtime`, `,`, `Ġwas`, `Ġa`, `Ġtime`, `Ġtime`, `Ġwho`, `Ġwas`, `Ġin`, `Ġthe`,
  `Ġhouse`, `Ġhouse`, `Ġin`, `Ċ`). These landing points are *measured from the
  official implementation*; they are this 70M checkpoint's own (repetitive)
  predictions, not a quality claim.
* **Reproduce / compare commands** (each verified below in **Local Run**):
  `python3 pythia-ppl.py --write-reference` regenerates the reference; the
  jit/offline candidates are checked with `python3 pythia-ppl.py --check
  output/jit_logits_f32.bin`; the weight-blob packing order is checked with
  `python3 pythia-ppl.py --weights arg0.data`.
* **Agreed tolerance:** `np.allclose(atol=1e-3, rtol=1e-3)` on the complete
  logits tensor plus exact per-position argmax agreement (metrics in the
  manifest), and recon-weights ppl within `PPL_TOL = 0.05` of the canonical
  ppl. Element-wise tolerance is the auxiliary gate of this stage — the
  conclusion is the discrete argmax / ppl agreement (see **Known Limitation**
  #7 for why a pure absolute bound does not fit).

## Local Run

**Device: host CPU** (x86-64). The host has an NVIDIA A800, but no CUDA-enabled
Python toolchain exists in this environment (`torch.cuda.is_available()` →
`False` in `result/bin/python3`, and the buddy ExecutionEngine is a host-CPU
LLVM JIT with no GPU codegen path — see **Known Limitation** #4). The official
single forward is **0.009–0.017 s** on CPU; the full TOSA→LLVM jit inference of
the imported graph is **23.9 s** after a 122 s one-off jit compile.

Environment (nix develop of the buckyball repo; `result/bin/python3` = Python
3.14.6 with `torch 2.12.0`, `transformers 5.5.4`, `huggingface_hub 1.16.0`):

```bash
cd /home/ROXY/code/bb_work/buckyball
export BB=$PWD RISCV=$BB/result
export BUDDY_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/build
export LLVM_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/llvm/build
export PYTHONPATH="$LLVM_MLIR_BUILD_DIR/tools/mlir/python_packages/mlir_core:$BUDDY_MLIR_BUILD_DIR/python_packages"
export HF_HUB_OFFLINE=1
# this host's harness *_proxy vars break httpx URL parsing; keep http(s)_proxy
# or strip them all for the offline runs below (same quirk as the BertMedium round)

cd bb-tests/workloads/src/ModelTest/e2e/models/models/Pythia
# 1) canonical reference (official implementation)
python3 pythia-ppl.py --write-reference
# 2) local run: AOT import + execute the imported graph on the host CPU
python3 import-pythia.py --output-dir . --jit-check \
        --dump-candidate output/jit_logits_f32.bin
# 3) independent re-check of the dumped output through the workload's own checker
python3 pythia-ppl.py --check output/jit_logits_f32.bin
# 4) packing-order check: inject arg0.data into a fresh official model
python3 pythia-ppl.py --weights arg0.data
```

The **local carrier chosen for this stage is the importer's own host execution
path** (step 2, a `--jit-check` host run of the imported graph) plus the
workload's own checker (step 3) and the recon-weights ppl (step 4). This
carrier is a **team-side addition, not a general upstream form** (upstream's
chip-agnostic host form is the `.rax` + `buddy-cli` runner-plugin packaging,
which Pythia does not carry); the `.rax` form was not chosen because it requires
a runner plugin/spec manifest this model lacks. Same carrier decision as the
BertMedium round.

does and then executes **that same imported graph** on the host CPU through the
buddy frontend's own TOSA → LLVM pipeline and MLIR `ExecutionEngine`, i.e. a

## Build Binding

Configure and build were run through CMake/Ninja directly (the
`bbdev workload --build` path needs the chip layout that this stage
deliberately does not add — see **Known Limitation** #2). The upstream
`e2e/models/lib/CMakeLists.txt` gate requires per-chip compiler targets, so a
chip-less configure needs the same shim bbdev injects: `BUCKYBALL_TARGETS` plus
an ISA dir generated from the chip.pb (`pb_to_target_registry.py --isa-dir`, the
pebble chip.pb already installed under
`examples/chips/pebble/configs/generated/chip.pb`).

```bash
cd /home/ROXY/code/bb_work/buckyball
export BB=$PWD RISCV=$BB/result
export BUDDY_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/build
export LLVM_MLIR_BUILD_DIR=$BB/compiler/thirdparty/buddy-mlir/llvm/build
export PYTHONPATH="$LLVM_MLIR_BUILD_DIR/tools/mlir/python_packages/mlir_core:$BUDDY_MLIR_BUILD_DIR/python_packages"
export HF_HUB_OFFLINE=1
python3 compiler/scripts/pb_to_target_registry.py --repo $PWD \
  --chip-pb examples/chips/pebble/configs/generated/chip.pb \
  --isa-dir .dsh/pythia-isa --print-targets   # prints: pebble

cmake -S bb-tests/workloads/src/ModelTest/e2e/models -B .dsh/build-pythia -G Ninja \
      -DMODEL=pythia -DWORKLOAD_LIB_DIR=$BB/bb-tests/workloads/lib \
      -DPython3_EXECUTABLE=$BB/result/bin/python3 \
      -DBUCKYBALL_TARGETS=pebble -DBUCKYBALL_ISA_DIR=$BB/.dsh/pythia-isa
# -- Enabled model: pythia
# -- Configuring done (2.2s) / -- Generating done (0.0s)

rm -f bb-tests/workloads/src/ModelTest/e2e/models/models/Pythia/{forward.mlir,subgraph0.mlir,arg0.data}
cmake --build .dsh/build-pythia --target pythia-model-build
# [1/1] Generating Pythia forward.mlir, subgraph0.mlir and parameters
# importing EleutherAI/pythia-70m: input_ids=(1, 16) ([10758, ..., 15])
# forward.mlir + 1 subgraph(s) -> .../models/Pythia
# arg0.data: 70426632 float32 (281706528 bytes) bit-exact
```

The two registration points required at this stage (verified by
`buckyball_workload_audit`):

1. `bb-tests/workloads/src/ModelTest/e2e/models/CMakeLists.txt` — `PYTHIA`
   appended to the `foreach(model_flag IN ITEMS ...)` MODEL reset list (so
   `-DMODEL=<other>` clears it).
2. `bb-tests/workloads/src/ModelTest/e2e/models/models/CMakeLists.txt` —
   `set(MODEL_PYTHIA_DIR ${MODEL_DIR}/Pythia)` plus
   `if (MODEL_PYTHIA) add_subdirectory(Pythia) endif()`.

The model directory's CMakeLists produces no executable (`*-run` targets live
in `archs/` and belong to the bind round).

## Known Limitation

1. **`buddy-pythia-main.cpp` is not compiled or run in this stage.** Linking it
   needs the chip-bound `buddy-opt`/`buddy-translate`/`buddy-llc` pipeline,
   explicitly out of scope here. It is checked two ways instead: its
   `extern "C"` declaration and sizes match the `@forward` signature read from
   the emitted `forward.mlir` (`memref<70426632xf32>`, `memref<1x16xi64>` in,
   `memref<1x16x50304xf32>` out), and `g++ -std=c++17 -fsyntax-only -Wall`
   passes against the buddy headers (see **Build Binding**).
2. **Pythia has no pebble-bind assets yet — it is NOT bound.** By design this
   stage adds no `archs/buckyball/pebble/Pythia/` layout, no bbdev
   `MODEL_LAYOUT` entry and no parent `bb-tests/workloads/scripts/build.py::_MODELS`
   entry, so `workload --build '--chip pebble'` (the expected CI test of this
   round) cannot select this model yet. The chip-bind round (later stage,
   chip-lead territory) owns that work; `chip: pebble` in this round's checklist
   is an intention, not a binding.
3. **The driver takes fixed input ids, not a C++ tokenization.** gpt_neox uses
   the GPT-2 byte-level BPE tokenizer, which buddy's `TextContainer` does not
   implement (it has Bert/Llama/Qwen3/Gemma4 tokenizers only). The ids are
   hardcoded from the official tokenizer's output (committed in
   `reference/reference_manifest.json`); `vocab.txt` is committed for id→token
   display. A C++ gpt-neox tokenizer, if ever needed by a later stage, would be
   an upstream toolchain addition, not part of this workload.
4. **Host-CPU jit inference exceeds the 10 s per-inference rule; GPU is not
   available for this path.** The single ExecutionEngine forward measured 23.9 s
   (122 s one-off jit compile, 281.7 MB parameters). The playbook says to switch
   to local GPU when a single forward exceeds 10 s; this environment cannot:
   `torch.cuda.is_available()` is False in the only Python toolchain (a CPU-only
   nix torch), and the buddy ExecutionEngine lowers to host-CPU LLVM JIT with no
   GPU codegen path. The canonical reference producer (official aten forward) is
   0.012 s on CPU, well under the rule. Recorded here rather than silently
   switching carriers (same finding as the BertMedium round).
5. **The importer traces one full forward (no KV-cache decode).** The Qwen3
   precedent additionally imports prefill/decode graphs with `StaticCache` and
   carries `trace/` tomls — those are the later quant / cycle-trace / bind
   rounds' assets of the same model, deliberately not copied at this stage. The
   `quant/` and `trace/` dirs do not exist under `Pythia/` yet.
6. **`max_abs_diff` is 0.0098 while `atol` is 1e-3.** pythia-70m's logits reach
   magnitudes ~1e3 at the top positions, so a pure absolute bound is the wrong
   yardstick: `max_rel_diff` is 2.3e-5 and relative-L2 is 1.6e-6, and
   `np.allclose(atol=1e-3, rtol=1e-3)` passes along with exact per-position
   argmax agreement — that is the agreed metric (manifest `tolerance`).
7. **The per-position argmaxes are this checkpoint's measured values.** A 70M
   model's greedy predictions repeat (`Ġtime`, `Ġhouse`, …); they are
   deterministic outputs of the official implementation, not a quality claim,
   and they are stable across the two numerical paths (jit argmax list is
   byte-identical to the official one).
8. **Hub access and proxies.** This host reaches HuggingFace only through a
   local HTTP proxy; the harness's `ALL_PROXY`/`no_proxy`/`NODE_USE_ENV_PROXY`
   vars break httpx URL parsing in this Python (same quirk as the BertMedium
   round), and `HF_ENDPOINT=https://hf-mirror.com` can reject the mirror's
   redirect, so downloads ran with `HF_ENDPOINT` unset and only `http(s)_proxy`
   kept. `pythia-ppl.py` loads with `local_files_only=True` (the model must be
   in the hub cache at the snapshot commit `a39f36b1...`, or reachable via the
   `PYTHIA_70M_MODEL_PATH` override); the committed workload consumes only
   committed/regenerable assets with `HF_HUB_OFFLINE=1`.
9. **A 3.2 MB binary reference file is committed.** It is the full canonical
   logits tensor, which the "compare the complete output, not just an argmax"
   rule calls for; it is regenerable via `pythia-ppl.py --write-reference` and
   pinned by the sha256 in `reference/reference_manifest.json`. The 281.7 MB
   `arg0.data` blob and the `.mlir` artifacts are generated and gitignored.
10. **Tokenizer tail ids.** The official tokenizer only maps ids 0–50276;
    vocab rows 50277–50303 exist in the checkpoint but correspond to no
    tokenizer token (vocab.txt carries `<unused_N>` placeholders for them). The
    canonical argmaxes never land there, but the model side keeps the full
    50304-line vocabulary for index stability.
